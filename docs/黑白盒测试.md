# 黑盒 / 白盒（网页联调口径）

**日期：** 2026-11-15（2026-11-16 补本机 TCP）  
**入口：** 网页案情板 `python3 ui_prototype/server.py`，浏览器打开 `http://localhost:8080/ui_prototype/index.html`。本机 TCP 用终端 `client_transfer --mode tcp`。  
**角色：** 陈是房主，彭、刘是侦探，王只开 `room_server` 和 `relay_server`，不进房。本机 TCP 由刘在同一台 WSL 上分两个终端完成。  
**范围：** 11 月 15 日网页测 UDP 打洞和中继。11 月 16 日补本机 TCP 直连。自动模式不作为单独一轮。

房主还在时，后进的人按位图向已经有块的人要块。陈点「离开」后同一局接着玩，不重新生成案卷，王不重启房间服。

## 1. 黑盒

只看网页表现，不看源码。两种方法：等价类划分、边界值分析。

### 1.1 等价类划分

| 类 | 有效输入 | 无效输入 | 应看到 |
|----|----------|----------|--------|
| 连接方式 | UDP 打洞；中继；本机 TCP 直连 | 自动模式不单列 | 网页 UDP：路径「打洞」。网页中继：路径「中继」。终端 TCP：路径「本网直连」 |
| 取块来源 | 只有陈有块；陈和彭都有块；陈已离开、彭还有全套 | 房里没有任何完整副本 | 来源依次是「陈」、陈和彭都出现、「彭」。无人持有时停在未齐，不能变成「已有」 |
| 进房人数 | 1～4 人 | 第 5 人 | 前 4 人「已入房」；第 5 人报错 |
| 昵称 | 1～16 字节 | 17 字节 | 16 字节能进房；17 字节进不了房 |
| 本地缓存 | 空的 `ui_prototype/session_*` | 留下旧案卷再进同一局 | 空缓存才会重新拉取。旧缓存会续传，来源变成「本地」，不能当互传证据 |

房主主机填王这台机器的 IPv4。王日志里看到的客户端地址（例如 `.2` 陈、`.4` 彭）不是这一栏。

### 1.2 边界值分析

| 边界 | 边界内 | 边界外 |
|------|--------|--------|
| 房间人数 | 第 4 人仍「已入房」 | 第 5 人 `ROOM_ERROR 0005` |
| 昵称长度 | 16 个 `a` | 17 个 `a` |
| 打洞重试 | 第 4 次仍是打洞 | 第 5 次变成回落中继 |

房间人数的上界来自房间服：侦探的 `peer_id` 从 2 递增，大于 4 返回 `ERR_ROOM_FULL`（`0x0005`）。昵称上界是 16 字节，客户端参数和 `JOIN_REQ` 都按这个长度拒绝。打洞重试上界是 5 次，第 5 次把该对端标成回落中继。

### 1.3 要截的图

1. 至少两端的成员区：陈、彭、刘的昵称、peer、地址。
2. 房主还在、彭已经有块时，刘的证物卡。来源里要同时出现「陈」和「彭」。这是互传的主图。
3. 陈点「离开」之后，刘接着下，来源变成「彭」。同一局号，没有重新生成。
4. UDP 这一轮：路径「打洞」，三个证物「已有」。
5. 中继这一轮：路径「中继」，三个证物「已有」。
6. 本机 TCP（终端，不是网页）：路径「本网直连」，三个证物来源都是陈。局号 `A109B741`，房间地址 `127.0.0.1`。

第 4 人成功、第 5 人 `0005`、16/17 字节昵称，若当天没有作为正式证据留下，补测再截。

陈离开之前，彭的三件证物必须已经下齐，并且彭留在房里。刘已经进房就不要退出、不要清 `ui_prototype/session_*`。王的 `room_server` 保持运行。陈自己的三件来源是「本地」，那是本机案卷，不算收到别人的块。

## 2. 白盒

看路径选择和「向谁要块」。网页的 UDP / 中继都不带 `--cs`，所以不会锁死只向房主要。

`src/transfer/transfer.c` 里 `route()`：

```c
static int route(struct transfer *t,int id) {
    struct peer *p=&t->peers[id];struct connection *c=link_for(t,id);
    if(!t->mode && c && !c->connecting) return PATH_LAN_TCP;
    if(t->mode!=2 && p->udp_ok && !p->fallback) return PATH_PUNCH;
    if(t->mode==2 || p->fallback) {c=relay_for(t);if(c && !c->connecting)return PATH_RELAY;}
    return 0;
}
```

`--mode udp` 时 `mode=1`，`--mode relay` 时 `mode=2`。网页「UDP 打洞」走第二句，「中继」走第三句。

同文件里的要块循环：

```c
for(int turn=0;turn<4;turn++){int id=1+(t->cursor+turn)%4;if(id==t->id || (t->cs_only && id!=1))continue;
    struct peer *p=&t->peers[id];int path=route(t,id);if(!path || p->pending)continue;
    for(int f=0;f<3 && !p->pending;f++)for(unsigned k=0;k<t->manifest.files[f].piece_count;k++){
        if(!(p->bits[f]&(1u<<k)) || (t->have[f]&(1u<<k)))continue;
```

`t->cs_only && id!=1` 才是「只向房主要」，对应实验 8 的中心分发对照。这次网页没开这个开关。循环会找任何位图里已经有该块的 peer，所以房主在线时也会向彭要。

打洞失败的边界，同一文件：

```c
if(p->path==PATH_PUNCH){
    p->retries++;event(t,"UDP_RETRY",id,p->retries);
    if(p->retries>=5){p->fallback=1;p->pending=0;need_relay=1;event(t,"UDP_FALLBACK",id,5);continue;}
```

### 2.1 六种覆盖

六种覆盖都对着 `mode!=2 && udp_ok && !fallback` 这一句。

| 覆盖 | 要打到的路径 |
|------|----------------|
| 语句 | UDP 轮走到 `return PATH_PUNCH`；中继轮走到 `return PATH_RELAY`；要块循环走到「位图有块就请求」 |
| 判定 | 这一句一次为真（打洞成功），一次为假（连接方式选中继） |
| 条件 | `mode!=2`、`udp_ok`、`!fallback` 各自有真有假：打洞成功、选了中继、已进房但还没有 `UDP_READY` |
| 判定/条件 | 上一行的判定和条件一起满足 |
| 组合 | 稳定的两组是「三个条件全真 → 打洞」和「`mode==2` → 中继」。`fallback=1` 要看到 `UDP_FALLBACK`，现场没有就用 `python3 -u tests/test_transfer.py --case udp-all` |
| 路径 | 打洞返回、中继返回、通道未就绪时 `return 0`。本机 TCP 轮走到 `PATH_LAN_TCP`（路径「本网直连」） |

### 2.2 白盒留证

白盒截图是王的前台日志，不是网页：

- `room_server`：`JOIN`，以及 `PROBE` 的反射端口不是 0
- 客户端：`UDP_READY` 或 `RELAY_CONNECTED`
- `relay_server`：中继轮的 `RELAY_FORWARD`，并带 `inner=`

## 3. 和实验 8 的关系

实验 8 比较的是同一局、同样三端、同样限速下的两种取块方式。中心分发只向 `peer_id == 1` 要。互传向位图上的持有者要。公式是：

源节点上传减少比例 = 1 −（互传方式下源节点证物上传字节 ÷ 中心分发方式下源节点证物上传字节）

以实测为准，可以为零，也可以为负。网页这次走的是互传，不是中心分发。
